# ADR-001 — Fondasi aplikasi standar

Keputusan: Next.js App Router + TypeScript + Tailwind CSS, Supabase Auth dan PostgreSQL, Zod untuk boundary API, npm dengan versi dependency exact serta package-lock.json. Runtime diuji: Node 24.22.1 / npm 11.9.0.

Source Vinext di reference_partial_source tetap merupakan arsip; tidak dikompilasi, diinstal, atau dijadikan autentikasi aplikasi baru. Tidak memakai header identitas gateway ChatGPT. Tidak ada localStorage sebagai penyimpanan domain, service-role pada CRUD, Redis, atau panggilan model.

Sesi divalidasi dengan Supabase getUser dan immutable OWNER_AUTH_USER_ID pada server. Database membatasi satu profiles row yang diprovision admin. RLS melindungi pembacaan; grant tulis langsung dicabut. Fungsi transactional SECURITY DEFINER memakai search_path kosong, require_owner, field allowlist dan expected revision. Audit dan outbox berada dalam transaksi domain. Outbox saat ini ditandai blocked, belum dikonsumsi worker.

Milestone tanggal saja memakai PostgreSQL DATE. Instant wajib menyertakan offset dan zona IANA, bukan konversi wall time ambigu secara diam-diam. Recurrence, provider projection dan pemeriksaan konflik menyeluruh memerlukan WP03–04; tidak diklaim selesai.

PGlite menjalankan PostgreSQL aktual dalam WASM untuk migration/RLS/rollback tests. Fixture HTTP Supabase dipakai hanya untuk E2E lokal. Ini tidak membuktikan konfigurasi Supabase hosted atau pengiriman email sebenarnya.

## Agenda interval dan zona waktu

Agenda memakai `@js-temporal/polyfill@0.5.1`, dependency exact dengan lockfile, untuk batas tanggal pada zona IANA dan perbandingan nanodetik. Paket ini merupakan implementasi komunitas; bukan paket resmi TC39. Import eksplisit hanya dipakai dalam perhitungan server dan tests, tanpa mengganti global Temporal. Date-only tidak dikonversi menjadi komitmen penuh; batas hari hanya membantu mendeteksi potensi bentrok. DST memakai panjang hari sebenarnya. Detail cakupan, buffer, batas sumber dan fitur tertunda ada di AGENDA.md. Tidak ada perubahan schema/migrasi untuk fitur ini.

## Agenda source paging

Batas satu query 1.000 baris diganti keyset berdasarkan primary key UUID, halaman maksimal 500, batas 10.000 baris dan 100 request halaman. Short page tidak membuktikan akhir sumber. Exact count awal dan HEAD count akhir merupakan pemeriksaan kardinalitas untuk status cakupan; bukan snapshot transaksi dan tidak mendeteksi setiap edit bersamaan. Cursor tidak maju, count hilang/berubah/tidak cocok dan cap menurunkan status kelengkapan. Error provider tetap gagal tertutup. Ini hanya memakai SELECT existing, tanpa perubahan schema, RPC atau dependency.

## Bridge MCP tanpa backend live

Adapter stdio terpisah memakai SDK MCP resmi yang dipin exact dan Zod strict. SQLite bawaan Node menyimpan hash payload, intent key dan waktu untuk retry setelah restart; tidak menyimpan token atau isi draft. Credential file dan ledger berada di luar repository. API agent/grant WP06 tetap prasyarat live; adapter tidak memakai cookie website atau Supabase key. Config contoh handoff lama dipertahankan sebagai referensi historis, bukan konfigurasi yang dianggap sudah diuji. Pemisahan ini memungkinkan contract harness tanpa mengaktifkan Hermes/Telegram/model atau menulis ke database hosted.

## Backend agent WP06 — kelanjutan

API/grant WP06 kini diimplementasikan dan diuji lokal; migrasi baru belum diterapkan hosted. Backend memakai client anonymous terpisah dari sesi website. Public RPC untuk role anon memverifikasi raw token opaque, hash, scope, expiry/revoke, status Auth owner dan rate window pada setiap panggilan. Private helper memakai SECURITY DEFINER dengan search_path kosong, explicit grants dan owner yang berasal dari grant. Tidak ada service-role key. Tabel credential/receipt privat memakai RLS tanpa policy publik. Jangan mencatat header/body/parameter RPC yang membawa token. Public schema advisors perlu ditinjau saat penerapan hosted.

Credential mint/revoke memerlukan owner session; bearer ditolak pada kanal website dan cookie tidak mengautentikasi kanal agent. Shared persist_draft menjaga transaksi domain/history/outbox lintas kanal; receipt website tetap terpisah dari receipt per integration. SQL hashes untuk token tidak dapat dipakai sebagai credential mentah. Rate/last-used termasuk transaksi dan rollback jika mutation gagal. Detail batas, pagination UUID, retensi dan gate live ada di AGENT_API.md.
